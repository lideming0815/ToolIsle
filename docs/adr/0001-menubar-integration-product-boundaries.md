# ADR-0001：菜单栏融合的首版产品边界

日期：2026-09-26。状态：已接受（用户确认 1A、2A、3A、4A、5A、6A、7A、8B、9A、10A，指定复用 `publish/` 生成完整 DMG，并在方案汇总后确认总体方案）。

用户希望只安装一个 App，设置和功能尽量统一，同时让 ToolIsle 与菜单栏项目都容易同步上游。首版将常用操作与设置统一到 ToolIsle；搜索、图标排序等高级操作可以使用独立窗口，不要求将完整图标列表或拖拽编辑器嵌入刘海。

“一个 App”指一个安装的外层应用包，允许内部有辅助进程，但安装、启动、退出和应用升级应统一管理。系统如果需要为辅助组件单独授权，用户接受额外的权限条目与授权步骤，由融合版提供清晰的统一引导；具体权限归属与升级后授权保留仍需实机验证。

菜单栏能力采用 Thaw，因其已有动作与设置控制接口，能减少为统一设置而新增的接口维护。允许 ToolIsle 增加入口和设置页，允许 Thaw 调整身份、启停、更新及窗口等发行行为，但不修改菜单栏核心算法；若实现必须越过该边界，先由用户决定删减需求还是扩大修改范围。

首版沿用 `publish/` 的现有发布脚本生成完整 DMG，通过手动替换整个融合版 App 升级，内部组件不单独更新，也不建设首版应用内更新渠道。两套上游代码仍可分别同步，经构建与验证后随新的完整 DMG 交付。

首版统一切换隐藏区、打开搜索、更多菜单栏设置三个操作，以及自动重新隐藏（开关、触发方式、定时延迟）、鼠标悬停展开（开关、等待时间）、当前屏幕 Thaw Bar 开关。除 ToolIsle 设置页和菜单入口外，在刘海面板提供快捷操作；不嵌入完整图标编辑器。高级窗口沿用 Thaw 的名称与原生界面，将统一体验集中在常用路径，以减少界面补丁的维护成本。

首次安装后保持原有菜单栏状态，不启动菜单栏组件；用户点击刘海入口后进入权限引导，完成授权后启用。之后记住启用选择，让组件随主 App 启停。

总体方案已确认：以 ToolIsle 为主体，内嵌 Thaw 作为独立辅助进程；先验证签名、权限、通信与设置读回，再接入完整界面与既有 DMG 发布流程。方案确认不代表技术验证通过，签名、授权保留与运行行为仍需原型和实机验证。架构、异常处理建议、验证顺序与现有发布流程的限制见[融合方案](../research/thaw-integration-options.md)。

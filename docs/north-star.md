# 北极星目标

以尽可能小、清晰且可维护的定制差异，持续吸收 [ToolIsle 上游](https://github.com/lideming0815/ToolIsle)的更新，形成满足自己实际需求的定制版，并能重复构建为可在自己的 Mac 上安装使用的 DMG；有同事分发需求时，再扩展为适合同事安装的交付流程。

## 判断是否接近目标

一次完整闭环是：实现一项实际需要的定制 → 构建 DMG → 安装并验证 → 同步一个后续上游版本 → 再次构建、安装，确认定制及相关原有功能仍然可用。

完成二次开发和一次打包，只验证了闭环的前半段。

## 开发约束

- 低侵入以减少长期维护和合并冲突为目的。优先复用现有能力，将确有必要的源码修改保持在清晰、局部、可验证的范围内；不要求零源码修改，也不为隔离改动预建插件框架。
- 每项定制都应对应明确需求，并能与上游改动区分，便于理解、合并和必要时撤回。
- 持续跟踪上游意味着能够按需引入经过验证的上游版本；具体跟踪分支、版本节奏和合并策略在实施时确定。
- 构建产物应能追溯到对应的上游基线、定制提交和构建步骤，以便重复构建和排查问题。
- 定制版的应用升级必须保留定制身份与能力，避免安装后的升级意外换成不含定制功能的上游版。

## 分阶段完成条件

1. **自用基线**：复用仓库现有构建方式，产出 DMG，在自己的 Mac 上完成安装、启动和所需权限验证。
2. **首项定制**：加入一项明确的实际需求，产出新的 DMG，确认定制生效、相关原有功能正常。
3. **上游同步闭环**：引入一个后续上游版本，记录冲突及必要适配，验证重新构建和安装后定制仍可用。
4. **同事分发（按需）**：在另一台目标 Mac 上验证安装和启动；接收者依照交付说明即可使用，无需本地编译。

## 后续需要明确

- 首项定制的具体需求及验收标准。
- 哪个上游分支或版本作为起点，以及何时同步后续更新。
- 若进入同事分发阶段，再确定目标机型和系统范围、安装体验及升级方式。

本文定义目标与验收方向；具体功能规格、架构、签名方式和发布自动化按实际阶段确定。
